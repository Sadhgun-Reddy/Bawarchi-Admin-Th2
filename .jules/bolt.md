## 2024-11-06 - Unnecessary computations in render loops
**Learning:** Found that `TopBar` was running a `flatMap` on `navigationConfig` on every single render to get the list of all routes. In addition, the `.filter` inside it was executing `searchQuery.toLowerCase()` on every iteration rather than computing it once per filter loop.
**Action:** When filtering a static list against a changing string input in React, ensure the static list calculation is outside the component (or memoized heavily), wrap the filtered result in `useMemo`, and hoist any loop-invariant computations (like `toLowerCase()`) outside the inner callback.
## 2024-05-15 - [Avoid Redundant String Operations in `.filter()`]
**Learning:** Found a performance anti-pattern in `src/pages/food-rescue/FoodRescuePage.tsx` where `.toLowerCase()` was being called on `searchQuery` up to three times *per item* inside the `.filter()` callback. In larger lists, this leads to unnecessary string allocations and wasted CPU cycles. Also, the filtered list was not memoized with `useMemo`, causing it to re-run on every render (even unrelated state changes like `activeTab` or selections).
**Action:** Always pre-compute the search query's lowercase value *before* entering the `.filter()` callback. Always wrap expensive filtering/mapping of large arrays in `useMemo` so that they only recalculate when their actual dependencies (the array or the search term) change.
